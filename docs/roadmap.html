ROADMAP / WHAT'S NEXT

Build it right.
Prove every layer.

Deliverables move forward when the service exists, the UI is connected and behaviour has been checked on supported hardware.

01 / FOUNDATION · INTEGRATED

AW1000 platform base

OpenWrt target, existing QuantumGrid React control centre, hardware-specific build configuration and first-boot flow. The firmware builder now consumes a validated device-profile manifest that binds the exact upstream target/subtarget/device symbol, configuration file, optional NSS/FXS inputs and expected firmware artifacts; the only admitted hardware profile is still the Arcadyan AW1000. The release pipeline packages a device-specific factory UBI image, temporary initramfs, build provenance and checksums; a guarded on-router installer preflights the original standard AW1000 MTD layout and refuses expanded or unknown layouts. The manifest is a build contract, not a declaration that unvalidated hardware is supported.

02 / VOICE · SOURCE INTEGRATED

RJ11 / FXS phone support

Upstream kernel driver, fxsd daemon, LuCI management page and setup guidance. Matching kernel and user-provided Skyworks patch required; hardware validation remains separate.

03 / NETWORK · PARTIALLY INTEGRATED

Real service-backed telemetry

Live system metrics, WAN interface byte/packet/error/drop counters from sysfs with scope filtering, support CSV export including successive-sample deltas, wireless radio state, iwinfo radio channel/frequency lists with restricted flags, regulatory country, supported 802.11 PHY generations and channel widths, current channel centers, driver-supported transmit-power levels (cached for 60 seconds), AP signal/noise, bitrate and transmit-power telemetry, iwinfo-associated Wi-Fi stations, searchable/sortable DHCPv4 lease inventory with filtered CSV export and modem/FXS status are integrated. The Security Center also exports read-only firewall zones, nftables table presence, DNS-filter configuration and VPN service/interface status without keys or credentials. The Security Center also performs a read-only posture review of the firewall service, config readability, fw4 runtime table and standard WAN/WWAN zone input/forward defaults. ACCEPT defaults are flagged for manual review; missing telemetry and custom zone naming remain explicitly unknown rather than being labelled secure. The Security Center also reports bounded WireGuard peer handshake age, RX/TX transfer counters and allowed IPs using a fixed read-only command, with measured per-peer RX/TX Mbps calculated from successive counter samples; first samples, resets, stale intervals and ambiguous duplicate interface/AllowedIPs tuples remain unavailable. All interface private keys, peer preshared keys, peer public keys and endpoints are discarded. It also lists up to 64 redacted UCI rule summaries (zone direction, protocol, target, ports and address-match presence) with local search/sort and CSV export; enabled ACCEPT rules sourced from WAN/WWAN-like or unrestricted source zones are flagged for review. Raw IP/MAC values and packet-path conclusions are not returned. Per-station signal/noise (average and current), RX/TX rates, HT/VHT/HE/EHT PHY, MCS, spatial streams, channel width, guard-interval metadata, byte/packet counters, inactivity, connection time and transmission retries/failures are shown when the driver exposes them. Per-station RX/TX throughput is derived from successive byte-counter samples; it is not inferred from WAN throughput. The station list sorts negotiated PHY rates independently from measured RX/TX throughput. The associated-client inventory summarises associated/authorized counts and measured throughput sample coverage, and supports local search, band and authorized/associated filtering, independent PHY/measured-throughput sorting and station-diagnostics CSV export with timestamp and applied-filter metadata. QMI registration, serving radio interface, roaming, data-session status and modem RF readings are displayed where returned; up to 30 distinct RF samples are retained in the current UI session without synthetic scores and can be exported as CSV with per-reading UTC timestamps. Current-channel busy airtime is estimated from iwinfo survey counter deltas where supported. A user-triggered iwinfo scan lists nearby access points with SSID/BSSID, band, channel, frequency, driver-reported signal/quality, encryption metadata, cipher suites and HT/VHT/HE/EHT operation width/center-channel information; missing security data remains Unknown. Results are rate-limited and cached. The UI groups observed BSSIDs by reported band/channel and surfaces strongest reported signal, but does not infer airtime or interference from scan counts. Scan inventories can be searched by SSID/BSSID/radio, band, channel, security or mode; filtered by band/security with reset, sorted locally, and exported using the visible result set plus scan time and applied-filter metadata to a spreadsheet-safe CSV and compared across the last ten distinct manual scans in the current UI session. Comparison identifies newly observed and no-longer-observed BSSIDs and ranks numeric signal changes for matching BSSIDs; missing observations are not interpreted as offline access points. Only the minimal network identifiers and signal fields needed for comparison are retained in page memory, with no browser-storage persistence. The comparison exports spreadsheet-safe CSV and the scan history has a clear-history action. Associated- client inventory also filters and sorts by driver-reported TX retries/failures; these are cumulative counters, not packet-loss scores. The Network page also inventories IPv4/IPv6 default routes and policy-routing rules, including lookup tables, priorities, firewall marks and interface selectors. A coverage view cross-references lookup tables with default routes, while keeping missing defaults distinct from invalid or unused policy. It also exposes the mwan3 daemon's interface and per-target health state, separate from netifd link state, with filtered CSV export, active IPv4/IPv6 policy weights and directly connected network sets. Per-WAN RX/TX throughput is measured from successive interface byte counters, and the export records the measured values and sampling interval; first samples, counter resets and stale intervals remain unavailable. Policy weights are not traffic-share measurements, and throughput is not a link-speed guarantee or controlled-load benchmark. These are read-only snapshots; they do not change failover policy or simulate packet paths. The Advanced page also reports firmware/board identity, a bounded installed `.ko` inventory from the running kernel's `modules.dep` compared with loaded entries from `/proc/modules`, service-script and diagnostic-tool presence, MTD partitions, block devices and important system mounts, including filesystem capacity/available space when statvfs is supported, through read-only checks. It reports Netfilter connection-tracking count, maximum, free capacity and 75%/90% thresholds, plus a 30-sample session-only occupancy trend and CSV export; unavailable kernel counters are not represented as zero. The Advanced page also surfaces a live uptime, CPU, memory, temperature and load-average snapshot, included in its spreadsheet-safe support CSV export. An on-demand five-packet ICMP test is integrated in Diagnostics with packet-loss percentage, RTT min/average/max and mean absolute consecutive-RTT variation (jitter). It uses a fixed target, same-origin administrator request and 30-second cache; it does not claim a controlled-load bufferbloat result. Opt-in, browser-local Wi-Fi client history is also available: an administrator can manually save snapshots of currently associated stations, retain 1, 7 or 30 days (up to 10,000 observations), export CSV and clear the history. It is disabled by default, stores MAC addresses and available DHCP hostname/IP details only in that browser's local storage, and is not uploaded, encrypted or synced. A snapshot is written only after the explicit Save snapshot action; it is not an automatic monitor. Automatic capture, continuous background scanning and fully automatic channel optimisation remain in development. The QuantumGrid usteer policy editor and weekly radio scheduler are integrated; native usteer remains disabled until an administrator configures the participating SSIDs and policy. Existing APs can now be edited through the QuantumGrid Wi-Fi page: SSID, WPA2/WPA3 security, passphrase preservation, hidden SSID, driver-listed channels, supported PHY/channel-width modes and reported transmit-power levels. Radio-wide changes use guarded UCI writes, an explicit disconnect acknowledgement and a Wi-Fi reload with a rollback attempt. The OpenWrt Apps page links into native LuCI pages and shows a bounded APK/OPKG inventory. It can refresh configured feeds, install named packages and remove non-core application packages through authenticated same-origin operations with explicit confirmation. The remover blocks base router services, LuCI core, kernel modules, Wi-Fi firmware/supplicants and NSS components; driver changes remain an offline firmware-build operation. Full package search/catalog parity with native LuCI Software is still not implemented. The AW1000 image includes upstream usteer and its LuCI app, but the daemon is disabled by default until the administrator configures the participating SSIDs and policy. These features do not yet replace every LuCI page. NSS/EDMA/PPE remains a research item: the current image is not yet a verified end-to-end NSS acceleration build. Office Networks includes guarded bridge-VLAN membership create/edit/remove; routed IPv4 segment provisioning on existing VLANs; DHCPv4 pool creation; firewall-zone attachment; narrow DHCP/DNS rules; explicit inter-zone forwarding create/remove; and existing-zone output/forward/masquerade policy controls. Segment creation requires a VLAN-filtered bridge with existing port membership and an internal firewall zone whose INPUT and FORWARD defaults are REJECT or DROP. IPv4-only remains the default, with a static L3 interface, DHCPv4 scope and three scoped DHCP/DNS rules. Optional dual-stack mode requests an OpenWrt delegated /64, enables DHCPv6 and Router Advertisements through odhcpd, and adds scoped DHCPv6, DNSv6 and ICMPv6 neighbour-discovery rules; it requires upstream IPv6-PD and an ACCEPT zone OUTPUT policy for Router Advertisement egress. Router INPUT and inter-zone FORWARD defaults remain unchanged and no inter-zone forwarding is added. Network, firewall, dnsmasq and odhcpd reloads are checked, with a cross-package UCI/service rollback attempt on failure. The Network page now manages persistent IPv4/IPv6 unicast routes on existing interfaces, with prefix/gateway/table validation, duplicate detection, administrator-client route protection, audited create/remove actions and network-reload rollback; default routes and policy rules remain separate controls. VLAN writes validate bridge membership and PVID conflicts and protect the current administrator IPv4 management path. Forwarding direction and zone policy changes are validated, audited and guarded by management-route checks for restrictive output changes. Lua validation and Node API contract tests are included in CI; CI success and physical AW1000/switch/client path validation remain separate release gates. Static SSID-to-L3-VLAN binding and allow-listed RADIUS dynamic VLAN assignment are now integrated for pre-provisioned IPv4 office segments. A constrained IPv4 inter-zone service-rule manager is integrated to add, enable/disable and remove one validated host/service between internal zones that already have an explicit forwarding; the rule targets a host in the destination zone's static subnet and can optionally constrain one source host. General-purpose firewall rule ordering, broad NAT/rule editing, downstream switch configuration and physical-path verification remain planned. Existing APs can now be bound to one validated non-WAN LAN/VLAN interface. The AP network list is snapshotted, Wi-Fi reload is checked and prior bindings are restored on failure. The active IPv4 management network cannot be removed from its carrying AP, and unknown management routes fail closed for existing bindings. Multiple simultaneous static network bindings, per-station VLANs outside the allow-listed RADIUS mappings, mesh and downstream switch provisioning remain planned. Guarded WAN-to-LAN IPv4 DNAT create/remove controls are integrated with source/destination zone validation, target subnet checks, duplicate external-port/protocol checks, firewall reload rollback and audit events. Managed IPv6 pinholes are also integrated: the administrator can allow TCP/UDP to one currently observed global-unicast NDP neighbour, with a valid unicast MAC and usable NDP state, and one destination port from an existing WAN/WWAN zone to an internal zone. Creation, enable/disable and removal use authenticated same-origin POSTs, explicit confirmation, scoped IPv6 firewall rules, audit events and checked reload rollback; enable-state changes restore the previous UCI value when a firewall reload fails. Private, link-local, multicast, documentation, special-purpose, unconfigured and unobserved IPv6 addresses are rejected; the control does not create NAT or change default zone policy. General-purpose IPv4 NAT/rule management, IDS, application-layer protections and physical WAN ingress testing remain separate release work.

04 / PERFORMANCE · PARTIALLY INTEGRATED

Gaming & intelligent QoS

The firmware includes SQM/CAKE packages and QuantumGrid reports configured queue rates plus runtime kernel qdisc statistics, which can be searched and sorted by byte, drop and backlog counters, then exported with the active filters for support review. The Gaming page edits enabled state, upload/download rates and bounded link-layer overhead/MPU values on existing SQM queues, with authenticated validation, complete option snapshots, restart checks and rollback attempts. Existing CAKE queues also expose four curated profiles: native defaults, best-effort, DiffServ 4 and DiffServ 8. Profile updates modify only the classification/fairness flags owned by QuantumGrid, preserve unrelated administrator qdisc options, require an existing CAKE queue and same-origin administrator POST, and restore both prior ingress and egress CAKE option values if restart fails. DiffServ presets rely on trusted DSCP markings; these controls do not prove ingress IFB pairing, bandwidth enforcement, latency improvement or end-to-end WAN behaviour. The Gaming page also provides audited, upload-only per-client DSCP marking: fixed BE, AF41, EF and CS1 classes are applied by firewall4 to forwarded packets matching one validated unicast MAC on an existing internal-source to WAN/WWAN-destination zone path. Policies are capped at 32, listed without exposing arbitrary firewall options, and removed with a firewall reload rollback if required. This sets DSCP on upload packets only; download-side marking, per-client bandwidth caps/guarantees and managed per-client queues remain planned. CAKE egress must use a DiffServ 4 or DiffServ 8 profile for DSCP tin selection, and effective packet-path behaviour still requires hardware testing. Diagnostics includes a bounded five-packet latency/loss/jitter sample, not a controlled-load bufferbloat benchmark. Download-side DSCP classification for unique static IPv4 DHCP reservations is integrated; per-client rate caps/guarantees, managed per-client queues and controlled-load bufferbloat tests remain planned.

05 / WIRELESS · PARTIALLY INTEGRATED

Wi-Fi intelligence & roaming

Radio diagnostics, scan-to-scan comparison and a read-only supported-channel shortlist weighted by observed BSSID signal and channel-width overlap are integrated. Existing APs can be edited for SSID, one existing static L3 network/VLAN binding, WPA2/WPA3-Personal and Enterprise security, hidden state, driver-listed channels, supported PHY/channel-width modes and driver-reported transmit-power levels, with administrator-route protection and Wi-Fi reload rollback. Enterprise APs can enable required RADIUS dynamic VLAN mode (dynamic_vlan=2) using up to 16 explicit native wifi-vlan mappings, each linked to an existing IPv4 routed office VLAN with switch-port membership and a default-deny firewall zone. Unmanaged hostapd VLAN settings are preserved and made read-only. EAP identity/certificate provisioning, RADIUS server management, fully automatic channel optimisation remains planned. Additional AP creation is supported on existing live radios using validated internal networks and runtime-verified Wi-Fi activation. Weekly radio schedules are integrated for existing radios, with explicit acknowledgement, router-local time windows, preservation of the original manual enabled state, live ubus verification and rollback handling. RADIUS EAP policy, server reachability, certificate trust and physical AP/switch/client VLAN validation are still separate release gates. Native LuCI usteer is included for opt-in multi-AP steering and disabled until SSID/policy configuration. A confidence-gated channel recommendation and explicitly acknowledged radio-wide apply path are integrated. Weekly radio scheduling is now available in the Wi-Fi page; continuous background scanning and fully automatic optimisation remain planned. The native usteer policy manager remains opt-in, and actual multi-AP roaming still requires physical AP/client validation.

06 / ACCELERATION · EXPERIMENTAL PROFILE

NSS / EDMA / PPE

The default stable firmware remains upstream OpenWrt. An opt-in AW1000 profile now targets the pinned qosmio 25.12-nss/Linux 6.12 fork with NSS 12.5 firmware, NSS core and ECM drivers, NSS Wi-Fi hooks, EDMA/PPE device-tree integration and guarded first-boot offload settings. QuantumGrid reports component presence in Advanced, but end-to-end NSS traffic offload remains unverified until physical AW1000 packet counters, throughput/latency benchmarks and recovery tests pass. DSA bridge-VLAN filtering must not be enabled on an NSS Wi-Fi-offload configuration.

Roadmap integrity.

Planned items are not shipped features. The roadmap will be updated as implementations, test results and supported device combinations are verified.
